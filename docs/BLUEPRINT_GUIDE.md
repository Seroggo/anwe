# SiteBlueprint Guide

## Определение

`SiteBlueprint` — формализованная переиспользуемая схема того, как должен быть устроен сайт определённого типа бизнеса.

Он описывает структуру и требования, которые можно повторно использовать для других компаний того же класса.

## Уровни библиотеки

### Core

То, что характерно почти для любого бизнес-сайта.

### Archetype

Общая логика сайта для класса бизнеса: производство, проектное производство, software product, digital service и т. п.

### Pattern

Повторяемая задача сайта независимо от отрасли: запрос расчёта, портфолио, загрузка файлов, лидогенерация.

### Vertical

Отраслевая специфика. Vertical расширяет общие слои и не должен копировать их содержимое.

## Состав SiteBlueprint

### `applicability`

Признаки того, к каким бизнесам применим blueprint.

### `structure.entities`

Сущности, которые сайт должен или может представлять.

### `structure.pages`

Типовые страницы и их назначение.

### `structure.blocks`

Типовые смысловые блоки страниц.

### `structure.actions`

Основные и дополнительные действия посетителя.

### `structure.evidence_types`

Какие типы доказательств помогают подтвердить предложение бизнеса.

### `conditional_rules`

Условия, при которых требуется дополнительная сущность, страница, блок или действие.

### `constraints`

Ограничения и предостережения, важные для корректного применения blueprint.

## Правило обобщения

Знание хранится на максимально общем уровне, где оно остаётся корректным.

Пример:

```text
contact                    → core
production_capability      → manufacturing archetype
quote_request              → quote-request pattern
PCB technical capability   → SMD vertical
```

## Правило reusable knowledge

В blueprint нельзя переносить индивидуальные факты исходного клиента.

Например, для SMD vertical допустимо указать, что сайту контрактного производителя нужно структурированно описывать производственные возможности.

Нельзя указывать конкретную модель оборудования SMD Service, если она не является свойством всей вертикали.

## Готовность blueprint

Blueprint можно считать подготовленным к review, если:

- он валиден по schema;
- его область применимости понятна;
- его структура достаточна для данного класса бизнеса;
- общие знания не дублируются в vertical;
- в нём нет индивидуальных фактов seed-проекта;
- conditional rules сформулированы явно;
- ограничения не маскируют предположения под факты.
